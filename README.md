# AlanaTech GPS — трекер на ESP32 + LoRa E32

```
 [NEO-6M] ──UART──> [ESP32 трекер] ──[E32 433 МГц]))) ~~~ (((  [E32]──> [ESP32 приёмник] ──Wi-Fi──> браузер
```

| Папка | Что это |
|---|---|
| [gps_tracker/](gps_tracker/) | ESP32 + NEO-6M + E32: раз в 5 с отправляет координаты по радио |
| [gps_receiver/](gps_receiver/) | ESP32 + E32: принимает пакеты, подключается к Wi-Fi `New BilimLand WI-FI`, показывает карту |

Оба проекта — PlatformIO (VS Code → расширение PlatformIO IDE).

## Подключение

E32 (на платах разные пины — на трекере GPIO16/17 заняты):

| E32-433T30D | ESP32 трекер | ESP32 приёмник |
|---|---|---|
| VCC | **5V (VIN)** — не 3.3V! | **5V (VIN)** |
| GND | GND | GND |
| TXD | GPIO26 | GPIO16 |
| RXD | GPIO27 | GPIO17 |
| M0 | GPIO25 | GPIO25 |
| M1 | GPIO18 | GPIO26 |
| AUX | не подключать | не подключать |

Только на трекере — NEO-6M:

| NEO-6M | ESP32 |
|---|---|
| VCC | 3.3V (или 5V, если на модуле есть стабилизатор) |
| GND | GND |
| TX | GPIO32 |
| RX | GPIO33 |

> ⚠️ **Никогда не включайте E32 без антенны** — на мощности 1 Вт выходной каскад сгорит.
> ⚠️ E32-433T30D при передаче берёт до ~700 мА. Питание от USB ноутбука может «проседать» —
> тогда ESP32 перезагружается (brownout). Поставьте конденсатор 470–1000 мкФ между VCC и GND модуля.
> При тесте на столе антенны должны быть на расстоянии хотя бы 1–2 м (1 Вт вплотную перегружает приёмник).

Пины меняются в `include/config.h` каждого проекта.

## Параметры радио

Обе прошивки при старте сами проверяют и при необходимости записывают одинаковую конфигурацию E32:
433 МГц (канал 0x17), адрес 0x0000, UART 9600, скорость в эфире 2.4 кбит/с, FEC, 30 дБм, прозрачный режим.

Формат пакета (≤ 58 байт, один радиопакет E32) описан в `lib/GpsProtocol/GpsProtocol.h`:
```
G,1,1234,1,51.128207,71.430411,347,12.3,9,0.9*50
```

## Прошивка

```bash
# трекер
cd gps_tracker
pio run -e tracker -t upload && pio device monitor

# приёмник
cd gps_receiver
pio run -e receiver -t upload && pio device monitor
```

`lib/GpsProtocol` и `lib/E32` одинаковые в обеих папках — при изменении правьте обе копии.

## Тестирование

### 1. Юнит-тесты протокола (без железа, на ПК)
```bash
cd gps_tracker  && pio test -e native
cd gps_receiver && pio test -e native
```
Проверяют кодирование/декодирование, отбрасывание битых и обрезанных пакетов, помещение в 58 байт, подсчёт потерь.
Нужен gcc в PATH (например, MSYS2 `C:\msys64\mingw64\bin`).

### 2. Проверка каждого модуля (Serial-монитор, 115200)
- Трекер: должно быть `[E32] конфигурация ОК` и строки `[GPS] символов=...` с растущим числом.
  Если `символов=0` — неправильно подключён TX NEO-6M.
- Приёмник: `[E32] конфигурация ОК`, `[WiFi] подключено, IP: ...`.

### 3. Радиоканал без GPS (в помещении)
Прошейте трекер тестовой прошивкой — она шлёт координаты по кругу вокруг центра Астаны:
```bash
cd gps_tracker && pio run -e tracker_fake -t upload
```
В логе приёмника появятся строки `[RX] id=1 seq=... fix=1 ...`, на странице `http://<IP приёмника>/` — движущаяся точка.

### 4. Автоматическая проверка связи с ПК
ПК должен быть в той же Wi-Fi сети:
```bash
python gps_receiver/tools/link_test.py <IP приёмника> -t 120
```
В конце — итог: принято / потеряно / % потерь и вердикт.

### 5. Настоящий GPS
Прошейте `-e tracker`, вынесите трекер на улицу или к окну. Холодный старт NEO-6M — до 5 минут
(на модуле замигает светодиод, когда есть фикс). На странице бейдж станет «GPS фикс», на карте появится трек.

## Веб-интерфейс приёмника

| Адрес | Что |
|---|---|
| `/` | карта + данные |
| `/api/last` | последний пакет, JSON |
| `/api/history` | трек (до 200 точек), JSON |
| `/api/status` | статистика приёма, Wi-Fi |
| `POST /api/reset` | сброс статистики |

Также доступно по `http://alanatech-gps.local/` (если сеть/ОС поддерживает mDNS).
Карта грузится из интернета (OpenStreetMap), таблица работает и без него.
