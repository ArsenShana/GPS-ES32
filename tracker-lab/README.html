ИНЖЕНЕРНЫЕ ФАЙЛЫ / R0

Сборка и прошивка.

Плата-носитель для существующего проекта ESP32 + NEO-6M + E32-433T30D. Модули вставляются в припаянные разъёмы: UART, управление радио и питание проходят по дорожкам. Это локальный радиотрекер с отдельным приёмником E32; SIM-карты и сотового модема в R0 нет.

Статус: рабочий сайт, программная симуляция, скомпилированная прошивка, разведённый проект PCB и CAD-корпус. Физическая плата ещё не изготовлена и не испытана. Перед заказом нужны сверка модулей, KiCad DRC/ERC и проверка схемы питания; производственные Gerber-файлы не выпущены.

1. Что выбрано за основу

Официальная схема ESP32-DevKitC V4, официальный футпринт ESP32 и руководство EBYTE с механическим чертежом E32 (раздел 3.4). Производитель предоставляет архив посадочных мест. Это набор исходных шаблонов модулей; готового проверенного шаблона всей нашей платы в проекте нет. Посадочные места и дорожки носителя созданы программно.

  • ESP32-DevKitC V4 WROOM, 38 контактов: 2×19, шаг 2.54 мм, между рядами 25.4 мм. Версия WROVER занимает GPIO16/17 памятью и не подходит. USB-C платы на 30 контактов не взаимозаменяемы с этим шаблоном.
  • Типовой NEO-6M breakout с антенной: в проекте принято VCC/RX/TX/GND и питание 3.3 В. До заказа проверить этот порядок, механические размеры и допустимость питания 3.3 В именно вашей платы.
  • E32-433T30D, 24×43 мм. Разворот модуля на 180°, контакты 1…7 слева направо у нижнего края. Угловая розетка размещает модуль горизонтально; её конкретную высоту и ориентацию надо сверить с реальным разъёмом.
  • Стабилизированные 5 В / 2 А через JPOWER. C1 1000 мкФ и C2 100 нФ рядом с E32. Прямое подключение к 12/24 В автомобиля не предусмотрено.

3. Корпус и пробная печать

Плата: 100×78×1.6 мм. Корпус: 114×92×29.4 мм. Толщина стенки и крышки 2.4 мм. Отдельные стойки для крепления PCB и крышки, отверстие для SMA и доступ к USB и питанию. Печатайте основание и крышку отдельно, плоской стороной на столе. Для редактирования есть STEP-сборка.

Начальные параметры пробной печати: слой 0.2 мм, 3–4 периметра. Горизонтальные отверстия могут потребовать поддержки. Сначала проверьте посадку на недорогой пробной печати. Размер винтов и их длину подберите после примерки: отверстия стоек 2.6 мм под самонарезающие M3, крышка имеет проходные отверстия 3.4 мм. Корпус не имеет уплотнения и подтверждённого IP-рейтинга. Для установки в нагревающейся машине отдельно выбираются материал и температурный режим.

4. Прошивка платы

До подключения USB снять JP1. При прошивке ESP32 питается от USB, а E32 — от отдельного 5 В на JPOWER; земля остаётся общей. Это исключает прямое объединение двух источников 5 В через носитель. Для автономного запуска USB отключить и вернуть JP1. Антенна должна быть подключена до запуска радио.

Из папки GPS-ES32/gps_tracker:

pio run -e carrier_fake -t upload
pio device monitor -b 115200

# После проверки радиоканала — настоящие координаты GPS:
pio run -e carrier -t upload

Если автоматический вход в загрузчик не срабатывает: зажать BOOT, нажать и отпустить EN, отпустить BOOT, затем загрузить прошивку. Carrier использует AUX=GPIO19 и мощность 21 dBm для первого стендового запуска. Тестовая версия отправляет маршрут вокруг Астаны каждые 5 секунд. Настройки существующего приёмника совместимы: 433 МГц, UART 9600, эфир 2.4 кбит/с, адрес 0x0000, прозрачный режим.

Обе версии скомпилированы для ESP32 WROOM с flash 4 MB. Полные образы: carrier-flash.bin и carrier-fake-flash.bin. Запись полного образа выполняется с адреса 0x0:

python -m esptool --chip esp32 --port <ваш-порт> write_flash 0x0 carrier-fake-flash.bin

Образ рассчитан на выбранную конфигурацию ESP32; для другой платы собрать исходники заново. Исходники находятся рядом с сайтом: ../gps_tracker/. Рабочая прошивка читает NMEA через TinyGPSPlus и передаёт реальные координаты. При ошибке настройки E32 или таймауте AUX передача пропускается. Сборка не подтверждает работу физического радио.

5. Что проверено программно

  • Обе сборки прошивки carrier / carrier_fake — успешны.
  • 7 существующих C++-тестов GPS-протокола — без ошибок.
  • 7 JavaScript-проверок симуляции и соответствия соединений, включая 1001 пакет из реального C++-кодека.
  • Независимая проверка платы: 13 цепей, 61 площадка, без несоединённых контактов и нарушений проверенного зазора 0.25 мм. Минимальный проверенный зазор дорожка/площадка 0.3275 мм. Эта проверка не заменяет KiCad DRC, ERC, тепловой расчёт и измерение питания.
  • CAD-проверка: основание и крышка — по одному валидному замкнутому телу. Отчёт CAD, отчёт PCB.

Сайт выполняет симуляцию обмена пакетами: не эмулирует ESP32, NMEA-приёмник, радиофизику, дальность связи и потребление. Реальные антенны, GPS-фикс, потери радио и устойчивость 5 В проверяются отдельно на собранном устройстве.

6. Воспроизведение проекта

Из папки GPS-ES32/tracker-lab:

npm ci
npm start
# Открыть http://localhost:4173

npm test
python3 tools/generate_pcb.py
python3 tools/validate_pcb.py

# Python 3.10–3.12, отдельное виртуальное окружение:
pip install -r tools/requirements.txt
python tools/generate_case.py

# Проверка браузера на macOS с Google Chrome:
npm run test:browser

Единый источник размеров: public/design.json. Носитель и схемы создаёт generate_pcb.py, корпус — generate_case.py, сайт — app.mjs, протокол — protocol.mjs. Размеры модулей и координаты разъёмов требуют согласованного изменения: часть footprint-координат зафиксирована в генераторе по выбранным модулям.

7. Следующий физический этап

  1. Сверить фото, контактные ряды и размеры ваших ESP32 и NEO-6M с выбранными версиями. Проверить угловую розетку E32 и высоту SMA.
  2. Открыть плату в KiCad, выполнить DRC, создать проверенную схему для ERC и проверить все непоключённые контакты. Оценить питание 5 В и 3.3 В под нагрузкой.
  3. После проверки выпустить Gerber, заказать 1–3 платы, напечатать пробный корпус.
  4. Подключить питание без модулей, измерить отсутствие короткого замыкания и полярность. Затем поставить модули и антенну, прошить carrier_fake.
  5. Проверить пакеты на существующем E32-приёмнике, затем прошить carrier, получить GPS-фикс на улице и проверить маршрут.
